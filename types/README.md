# @vega/api-types

TypeScript types for the Vega REST API, generated from `../docs/openapi.yaml`.

## What's in here

| File | What it is |
|------|------------|
| `api.ts` | Auto-generated by `openapi-typescript`. Every path, request/response shape, and component schema in the OpenAPI doc, as TypeScript types. |
| `events.ts` | Hand-maintained discriminated union of SSE event types emitted by `/api/v1/events`. The OpenAPI spec models the broker event generically; this file enumerates concrete event variants for type-narrowing in handlers. |
| `example.ts` | Reference snippets showing how to import + use the types. Not shipped at runtime. |

## How to consume (Cody)

Until this is published to npm, import via path or vendor a copy:

```ts
import type { components, paths } from '@vega/api-types'
import type { VegaEvent } from '@vega/api-types/events'

type IdentityResponse = components['schemas']['IdentityResponse']

const res = await fetch(`${baseURL}/api/v1/identity`, {
  headers: { Authorization: `Bearer ${token}` },
})
const identity: IdentityResponse = await res.json()
```

For full type-inferred fetch calls (without manual casts), pair this package
with [`openapi-fetch`](https://openapi-ts.dev/openapi-fetch/):

```ts
import createClient from 'openapi-fetch'
import type { paths } from '@vega/api-types'

const client = createClient<paths>({ baseUrl: 'https://acme.apex.io' })
const { data } = await client.GET('/api/v1/identity', {
  headers: { Authorization: `Bearer ${token}` },
})
// data is fully typed as IdentityResponse | undefined
```

## SSE events

EventSource can't carry custom headers; pass the access token as a query param:

```ts
import type { VegaEvent } from '@vega/api-types/events'

const url = `${baseURL}/api/v1/events?access_token=${encodeURIComponent(token)}`
const es = new EventSource(url)

for (const eventType of [
  'process.started', 'process.completed', 'process.failed',
  'workflow.completed', 'workflow.failed',
  'agent.created', 'agent.deleted',
  'chat.update', 'chat.event',
  'channel.message', 'channel.thread_reply',
] as const) {
  es.addEventListener(eventType, (e) => {
    const ev = JSON.parse((e as MessageEvent).data) as VegaEvent
    // ev.type is narrowed to eventType here
  })
}
```

See `events.ts` for the full discriminated-union shape and `example.ts:dispatchEvent`
for an exhaustiveness-checked switch pattern.

## Regenerating

```sh
npm install        # one-time
npm run generate   # rewrites api.ts from ../docs/openapi.yaml
npm run verify     # diffs the committed api.ts against a fresh generation
                   # (use in CI to catch drift)
```

Or from the govega root:

```sh
make types         # regenerate
make types-verify  # verify in-sync (no drift)
```

`api.ts` is committed so consumers don't need the toolchain. Whenever the
OpenAPI spec changes, regenerate and commit the result in the same PR.
